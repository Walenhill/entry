# Система записи на услуги (MVP)

> ⚠️ **ВНИМАНИЕ: ПРОЕКТ ЯВЛЯЕТСЯ ЭКСПЕРИМЕНТАЛЬНЫМ (MVP)**
>

Простой прототип системы бронирования для проверки идеи. Без лишних сложностей — только базовый функционал.

**Актуальность проекта:**
Данное решение идеально подходит для изучения и возможного использования. Благодаря отсутствию сложных интеграций и громоздких фреймворков, проект легко развернуть, поддерживать и масштабировать, обеспечивая клиентам удобный способ бронирования 24/7.

## Что умеет

**Для клиентов:**
- Посмотреть свободные слоты
- Забронировать слот (имя + телефон)

**Для администратора:**
- Войти по паролю (авторизация на основе PHP сессий)
- Создать слот вручную
- Сгенерировать слоты по шаблону (например, каждый час с 9 до 18)
- Видеть все брони и статистику
- Отменять/удалять слоты

## Технологии

- **Бэкенд:** PHP 8.2 (чистый, без фреймворков) + MySQL
- **Фронтенд:** Vue 3 + Vite
- **Инфраструктура:** Docker

## Как запустить

Для удобства разработчиков и пользователей мы подготовили несколько вариантов быстрого запуска проекта через Docker.

### Вариант 1: Быстрый запуск (Linux / macOS)
В корне проекта есть удобный скрипт, который автоматически скопирует `.env` файлы (если их нет) и запустит контейнеры:
```bash
./start.sh
```

### Вариант 2: Быстрый запуск (Windows)
Запустите командный файл:
```cmd
start.bat
```

### Вариант 3: Использование Makefile (Linux / macOS)
Для разработчиков, привыкших к Make:
```bash
make start  # Настроит .env и запустит проект
make stop   # Остановит проект
make logs   # Показать логи контейнеров
```

### Вариант 4: Вручную через Docker Compose
Если вы предпочитаете ручной запуск:
```bash
# 1. Скопируйте конфиги
cp backend/.env.example backend/.env
cp fronted-vue/.env.example fronted-vue/.env

# 2. Отредактируйте пароли в backend/.env (при необходимости)

# 3. Запустите
docker compose up -d --build
```

После успешного запуска приложение будет доступно:
- **Фронтенд:** http://localhost:5173
- **Бэкенд API:** http://localhost:8080

### Вариант 2: Без Docker

**Бэкенд:**
```bash
cd backend
# Убедитесь, что .env файл настроен для вашей локальной БД
php -S localhost:8080 main.php
```

**Фронтенд:**
```bash
cd fronted-vue
pnpm install
pnpm dev
```

## API Documentation

| Метод | Эндпоинт | Роль | Описание |
|-------|----------|------|----------|
| GET | `/slots` | Любой/Админ | Получение списка слотов. Клиенты видят только свободные, администраторы — все. |
| GET | `/slots/{id}` | Любой/Админ | Получение информации о конкретном слоте. Персональные данные клиента скрыты, если запрос не от администратора. |
| POST | `/slots/{id}/book` | Клиент | Бронирование свободного слота (требуется имя и телефон). |
| POST | `/auth/login` | - | Авторизация администратора. |
| POST | `/auth/logout` | Админ | Выход администратора (уничтожение сессии). |
| GET | `/stats` | Админ | Получение статистики по бронированиям. |
| POST | `/slots` | Админ | Создание нового одиночного слота. |
| POST | `/slots/generate`| Админ | Массовая генерация слотов по шаблону. |
| PUT | `/slots/{id}` | Админ | Обновление слота (в настоящий момент доступно только изменение описания). |
| DELETE| `/slots/{id}` | Админ | Удаление слота. |
| POST | `/slots/{id}/cancel`| Админ | Отмена существующего бронирования (перевод в статус "свободен" и очистка данных клиента). |

## Переменные окружения

**backend/.env:**
- `DB_HOST` - хост MySQL (по умолчанию mysql)
- `DB_PORT` - порт MySQL (по умолчанию 3306)
- `DB_DATABASE` - имя БД
- `DB_USERNAME` - пользователь БД
- `DB_PASSWORD` - пароль БД
- `MASTER_PASSWORD` - пароль администратора (хэшируется при первом входе)
- `APP_ENV` - окружение (например, development)
- `APP_DEBUG` - режим отладки (true/false)
- `FRONTEND_URL` - URL фронтенда для CORS (по умолчанию не задано, используются localhost:5173 и 127.0.0.1:5173)

**fronted-vue/.env:**
- `VITE_API_BASE_URL` - URL бэкенда (по умолчанию http://localhost:8080)

## Известные проблемы и ограничения архитектуры

Так как проект создавался как легковесный MVP, в нем есть ряд существенных ограничений, о которых нужно знать перед использованием:

- **Архитектура:** Бэкенд написан на "чистом" PHP без использования современных фреймворков (таких как Laravel или Symfony). Это упрощает быстрый старт, но усложняет поддержку и добавление сложной бизнес-логики.
- **Отсутствие кэширования:** В проекте не используются Redis или Memcached. При большом наплыве клиентов вся нагрузка ложится напрямую на MySQL, что может привести к проблемам с производительностью.
- **Масштабирование:** Авторизация администратора работает через стандартные PHP сессии в файлах. Это делает крайне сложным горизонтальное масштабирование (запуск нескольких контейнеров PHP), так как сессии не шарятся между ними.
- **Ограниченная бизнес-логика:**
  - Отсутствует ролевая модель. Сейчас есть только один администратор, невозможно добавить отдельных специалистов с ограниченными правами (подробнее в [ROADMAP.md](ROADMAP.md)).
  - Нет привязки слотов к конкретным услугам, нет интеграции с онлайн-оплатами.
- **Логирование и мониторинг:** Нет централизованной системы логирования ошибок (типа Sentry) или мониторинга, ошибки пишутся только в стандартные логи веб-сервера.
- **Тестирование:** Отсутствует стандартный тестовый фреймворк (например, PHPUnit). Юнит-тесты реализованы в виде отдельных PHP-скриптов в директории `backend/tests/`.
- **Безопасность фронтенда:** Состояние авторизации на фронтенде опирается на флаг `is_logged_in` в localStorage. Backend API не требует проверки CSRF-токенов.
- CORS строго ограничен в `backend/main.php` (разрешены только конкретные домены, например `http://localhost:5173`).

## Безопасность

- Пароли хэшируются через Argon2id и хранятся в БД.
- Сессионная авторизация с защищенными куки (HttpOnly, SameSite).
- Rate limiting: блокировка IP после 5 неудачных попыток на 15 минут.
- Валидация входных данных и защита от пересечения слотов по времени.
